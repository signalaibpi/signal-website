Executive, precise, restrained — a light canvas with a blue accent used sparingly for primary actions and diagnostic priorities, generous whitespace, and a strict grid with softened corners. Built with Next.js, TypeScript and Tailwind CSS (see `TECHNICAL.md`).

The homepage, AI Progress Review and Who we help pages use the same moderately compact spacing between sections; spacing within each section remains more generous for readability.

Visual design source of truth: `/Users/erikdekroon/Documents/Signal/Website/Signal Website Design Guidelines.md` (and `Gemini Image Style Guidelines.md` for imagery). Follow the design-doc split above — don't restate raw styling constants (colors, spacing, etc.) from those guidelines here; only document a visual fact once it carries behavioral meaning for a specific page.

When UI behavior, placement, visible labels, or page structure changes, update this document in the same change set.

## AI Progress Review

Route: `/ai-progress-review`

Renamed from the Business AI Diagnostic page (formerly `/business-ai-diagnostic`) on 2026-09-27 — only the route and its menu labels changed. The page's own content (browser tab title, hero, panels, dimension grid) still uses the Business AI Diagnostic wording below until Erik reworks it. The old URL is deliberately not redirected — Erik confirmed (2026-09-27) the site has no users yet.

### Purpose
- Explain what the Business AI Diagnostic does and make its assessment tangible before someone books time with Signal.
- Show all 12 dimensions the Diagnostic scores against, with enough detail (weight, what it measures, the underlying questions) to make the framework credible without overwhelming a first-time visitor.

### Sections (in order)
1. **Hero** — badge, headline ("Make your AI transformation measurable"), lead paragraph, single CTA ("View a sample diagnostic" — the copy doc defines only one CTA for this page's hero, unlike the homepage's two). Visual is a 12-wedge radial diagram (`DimensionsRadial`), one wedge per dimension, colour-coded by the same 4 area tokens as the homepage's dimension grid. Wedge length is illustrative only (not a real score or the dimension's weight) — see the code comment in `DimensionsRadial.tsx`.
2. **Why it applies** — the 3 panels from `Signal Website Copy.md` (Prioritise with a realistic view of readiness / Find what is holding AI back / Give teams clear improvement targets), styled like the homepage's benefit-card pattern but with this page's own copy (not a shared component).
3. **The 12 diagnostic dimensions** — intro paragraphs, then a grid of 12 interactive cards, one per dimension, in the same numbered order as the homepage's hero tile grid.

### Visual facts that carry meaning
- Each dimension card is a compact tile — a small number and area label (same font size as each other) above a bold name set in `on-surface-variant` gray (not near-black `on-surface`, and not area-coloured) — full black at this size/weight read as too heavy, so it uses the same softer gray as the site's body copy. The name is large enough that longer dimension names wrap to two lines on purpose (e.g. "Workforce AI Capability", "Policy and Control Assurance") rather than being shrunk to fit one line; the tile has a `min-h` tall enough for two lines so every card in a grid row still matches height whether its own title wraps or not. The number stays area-coloured for identity, but the title itself is deliberately kept neutral rather than area-coloured too — colouring both would make some cards look more prominent than others based on hue alone (e.g. Operation's muted slate vs. Strategy's vivid blue) rather than meaning. A small "View details →" label anchored at the bottom-right makes the interaction explicit while remaining subordinate to the dimension name; on pointer hover and keyboard focus, the card lifts slightly and gains a clearer border and shadow. Clicking/tapping a card opens a centered pop-up dialog (generous `p-12` padding so the text doesn't feel cramped; dimmed backdrop, closes on the X button, Escape, or a backdrop click) in the same area tint as the tile: number and "AREA, Weight N" on one line, the name repeated, a bold summary sentence, an "Example questions include:" label (the one piece of UI copy on this page that isn't from `Signal Website Copy.md` — added directly by Erik to make clear what the bullets below it are), then the dimension's underlying questions — everything else verbatim from the copy doc. This replaced two earlier approaches tried in this build: a drop-down overlay panel, then an in-place 3D flip — both were dropped because forcing every card to share one box size (needed for the flip) left most cards mostly empty to accommodate the longest dimension's content. The pop-up sizes itself to its own content instead, so short and long dimensions both fit naturally. No hover reveal — a pop-up appearing on mouseover would be too aggressive, so this is click/tap-only, which also sidesteps the hover-vs-touch race conditions the earlier approaches had to work around.
- Weight shown in the pop-up is the plain number from `Signal Website Copy.md` only (e.g. "Weight 4") — never a named tier (Supporting/Contributing/Major/Determining). Those names exist in `Signal Business AI Diagnostic.md` but that's the internal methodology doc, not approved website copy, so they're deliberately excluded from this page.
- All hero, panel, and dimension text is sourced verbatim from `Signal Website Copy.md`'s "Business AI Diagnostic" section, with one exception noted above (the pop-up's "Example questions include:" label) — nothing on this page is invented or pulled from the internal methodology doc.
- Photography is not sourced yet; this page currently has no image placeholders because none of its three sections call for one in the copy doc (unlike the homepage).

### States
- No loading, error, or empty states — the page is fully static with no data fetching.

## Who we help

Route: `/who-we-help`

### Purpose
- Show which sectors Signal specialises in (fintechs, business software companies, business process outsourcers) and where its approach also fits (insurance brokers & administrators, freight forwarders & trade services providers, accountancies, law firms).
- For each priority sector, connect the AI opportunity to the specific diagnostic dimensions that typically hold progress back and to how Signal's three services help.
- Let a visitor jump straight to the sector they care about.

### Sections (in order)
1. **Hero** — H1 "Who we help" (no badge: it would only repeat the H1) and the two intro paragraphs from `Signal Website Copy.md`. No CTA button, since the copy defines none. The right column is a sector navigator: three square image tiles for the priority sectors, then an "Also" list of the four other sectors as text rows with arrows. Every item jumps (smooth scroll, instant under reduced motion) to its sector section, landing just below the fixed header. The secondary sectors are deliberately text rows, not images or icons — seven image tiles at two sizes looked busy, and sector icons (gavel, ship, calculator) were rejected as cliché. On mobile the three tiles become rows with a small image, the name and an arrow.
2. **Who we specialise in** — one full-width section per priority sector on alternating backgrounds. A square photo sits in the left column (5 of 12) on every section — not alternating sides, because the three sections share one structure and are read comparatively — and stays pinned while the long text column scrolls on desktop. The text column holds, separated by thin rules: sector name and "The AI opportunity"; "Where AI can help" as tags; "What holds progress back" as a plain-text list followed by an "Explore the diagnostic dimensions" link to the top of `/ai-progress-review`; "How Signal helps" as a plain-text list of the three services. The copy's "Explore Signal's services" links are intentionally omitted — no services page is planned for now.
3. **Where our approach also fits** — heading and intro sentence, then one smaller section per secondary sector (not a grid), separated by thin rules: a small square photo, the name, the AI opportunity and "Where AI can help" tags.
4. **Final CTA** — the homepage's final CTA component, reused unchanged.

### Visual facts that carry meaning
- Each "What holds progress back" item carries a small label above the name — the dimension's number and area (e.g. "10 · GOVERNANCE") in that area's colour, matching the Diagnostic page. Number and area are looked up from the real dimension list by name, so every barrier must be one of the 12 real dimension names; a mismatch fails the build rather than showing a wrong label.
- Plain text, not cards, for barriers and services — Erik preferred it; the two lists share one style so they read consistently.
- Photography: seven square Atmosphere-style images showing the office environment of the teams named in the copy (not the end-customer experience — no card terminals or similar clichés). The three priority images appear both as hero tiles and in their sections; the four secondary images appear only in their sections. Until supplied, each frame shows a neutral decorative placeholder. Images are set per sector in `components/who-we-help/sectors-data.ts`.
- All sector text is verbatim from `Signal Website Copy.md` → "Who we help", except that "How Signal helps" descriptions are capitalised as standalone sentences (the copy writes them as lower-case fragments after "Name:").

### States
- No loading, error, or empty states — the page is fully static with no data fetching.
